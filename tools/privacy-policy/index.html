앱 개인정보처리방침 생성기

수집 항목과 사용 중인 SDK만 고르면 Google Play 심사에 필요한 개인정보처리방침이 한국어와 영어로 완성됩니다. HTML 파일로 받아 웹사이트에 그대로 올리세요.

법률 자문이 아닙니다. 이 도구는 일반적인 모바일 앱을 기준으로 한 서식을 만들어 줍니다. 실제 수집·이용 내용과 반드시 대조해 보시고, 민감정보나 결제·의료·금융 정보를 다루신다면 전문가 검토를 받으세요.

기본 정보를 채우고, 앱이 실제로 수집하는 항목과 사용 중인 SDK를 체크한 뒤 생성하기를 누르면 됩니다. 결과는 한국어와 영어 두 벌로 만들어지고, HTML 파일로 받아 웹사이트에 올린 다음 그 주소를 Play Console의 개인정보처리방침 URL 칸에 넣으시면 됩니다. 앱 안에서도 접근할 수 있도록 설정 화면 등에 링크를 하나 걸어두세요.

입력한 내용은 서버로 전송되지 않습니다. 전부 브라우저 안에서 문서를 조립하기 때문에 앱 정보나 이메일 주소가 외부로 나가지 않습니다.

Play 스토어가 요구하는 것

Google Play는 앱이 개인정보나 민감한 기기 정보에 접근하는 경우 개인정보처리방침을 요구합니다. 광고 SDK를 넣는 순간 광고 ID를 수집하게 되므로, 사실상 거의 모든 앱이 대상이라고 보시면 됩니다. 방침에는 최소한 다음이 명확히 적혀 있어야 합니다.

어떤 데이터를 수집하는지, 왜 수집하는지, 누구와 공유하는지, 얼마나 보관하고 어떻게 삭제하는지, 그리고 사용자가 문의할 연락처가 있어야 합니다. 여기에 더해 Play Console의 데이터 보안(Data safety) 양식에 적은 내용과 방침의 내용이 서로 어긋나면 심사에서 반려됩니다. 두 곳을 항상 같이 고치세요.

자주 놓치는 것

광고 SDK를 넣었다면 광고 ID(AAID) 수집을 반드시 명시해야 합니다. Firebase Analytics나 Crashlytics를 쓰면서 "아무것도 수집하지 않는다"고 적는 경우가 많은데, 이건 명백한 불일치라 반려 사유가 됩니다. 또 앱이 만 14세 미만을 대상으로 하거나 그럴 가능성이 있다면 Google Play의 가족 정책이 별도로 적용되므로, 아동 대상 항목을 체크해 관련 문구를 포함시키세요.

방침은 어디에 올리나요

공개된 URL이면 됩니다. 개인 웹사이트가 있으면 /privacy-policy.html 같은 경로에 올리는 게 가장 깔끔하고, 없다면 GitHub Pages나 블로그도 허용됩니다. 다만 로그인이 필요한 페이지, 다운로드만 되는 파일, 접근이 제한된 문서는 인정되지 않습니다. 앱을 업데이트할 때 수집 항목이 바뀌면 방침의 시행일도 함께 갱신하세요.
